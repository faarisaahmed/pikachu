Before you begin

One account, one program, one editor. Five minutes of setup.

A GitHub account

Free at github.com/signup. Pick a username you're happy to show a recruiter.

Git installed

Check with the command below. macOS ships it with the Xcode command line tools; Windows users install Git for Windows.

terminal
git --version

A text editor

Anything works. VS Code is the common default and has Git built into the sidebar.

Lesson 01

Create a repository and push your first commit

You'll take an ordinary folder, turn it into a Git repository, and mirror it to GitHub. This is the loop you'll repeat on every project from here on.

  1. Tell Git who you are

    Git stamps a name and email onto every commit. Set them once, globally.

    terminal
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"

    Use the same email as your GitHub account so your commits link back to your profile.

  2. Create the repository on GitHub

    Go to github.com/new, give it a name, and choose Public or Private. Leave every initialise checkbox unticked — an empty repository is easier to connect to a folder you already have.

  3. Make the folder on your machine

    Create a directory, move into it, and put something in it.

    terminal
    mkdir my-project
cd my-project
echo "# My Project" > README.md

  4. Initialise Git and commit

    init creates the hidden .git folder. add stages the changes you want to save, and commit writes them into history.

    terminal
    git init -b main
git add .
git commit -m "Initial commit"

    -b main names the first branch main, which is what GitHub expects.

  5. Connect the folder to GitHub and push

    origin is just a nickname for the remote URL. The -u flag links your local main to the remote one, so every push after this is a bare git push.

    terminal
    git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
    HTTPS or SSH? HTTPS is shown above and works everywhere. SSH skips the login prompt every time: generate a key with ssh-keygen -t ed25519, add the .pub file under Settings → SSH and GPG keys, then use the git@github.com:USERNAME/REPO.git form of the URL instead.

  6. The everyday loop

    From here on, this is the whole job. Run it whenever you finish a piece of work.

    terminal
    git status
git add .
git commit -m "Describe what changed"
git push
Lesson 02

Deploy the repository to GitHub Pages

GitHub will serve the files in your repository as a real website, free, over HTTPS. No server, no build step, no deploy command — publishing is just pushing.

  1. Make sure there's an index.html at the root

    Pages looks for index.html in the folder you publish from. That file is the front door of the site — everything else is linked from it.

  2. Turn Pages on

    In your repository: Settings → Pages. Under Build and deployment:

    • Source: Deploy from a branch
    • Branch: main, folder / (root)
    • Press Save

    The first build takes a minute or two. Watch it under the Actions tab if you're impatient.

  3. Visit your URL

    Pages builds the address from your username and repository name:

    url
    https://USERNAME.github.io/REPO/

    One exception: a repository named exactly USERNAME.github.io is served from the bare https://USERNAME.github.io root instead.

  4. Deploy again by pushing again

    There is no second deploy step. Every push to main republishes the site.

    terminal
    git add .
git commit -m "Update the homepage"
git push

  5. Two things that trip everyone up

    Absolute paths break on project sites. Your site lives under /REPO/, not /. Link to styles.css or ./img/logo.png, never /styles.css — the leading slash points at the domain root and will 404.
    Your browser caches aggressively. If a change doesn't show up, hard-reload (Cmd+Shift+R / Ctrl+Shift+R) before you go hunting for a bug that isn't there.
Lesson 03

Add collaborators and work as a team

Inviting someone takes thirty seconds. The habits that stop you overwriting each other's work take slightly longer — and matter far more.

  1. Send the invitation

    Settings → Collaborators → Add people. Search by GitHub username or the email on their account. They get an email invite that has to be accepted before they can push.

    On an organisation repository the same screen also sets a role — Read, Triage, Write, Maintain or Admin. Write is the normal choice for a teammate.

  2. They clone the repository

    Cloning downloads the project and wires up origin in one step.

    terminal
    git clone https://github.com/USERNAME/REPO.git
cd REPO

  3. Pull before you start, always

    Fetch everyone else's work before writing your own. This one habit prevents most merge conflicts.

    terminal
    git pull

  4. Work on a branch, not on main

    A branch is your own copy of the project. Break it freely — main stays untouched.

    terminal
    git checkout -b add-contact-page
# ...make your changes...
git add .
git commit -m "Add contact page"
git push -u origin add-contact-page

  5. Open a pull request

    After that push, GitHub shows a Compare & pull request banner. Opening a PR asks to merge your branch into main, and gives your teammates a place to review the change line by line before it lands. Merge it, then delete the branch.

  6. Protect main once the team grows

    Under Settings → Branches, add a rule for main requiring a pull request before merging. It stops anyone — including you at 2am — from pushing straight to the branch that's live on Pages.

    Hit a merge conflict? It only means two people edited the same lines. Git marks both versions in the file: delete the markers, keep the text you want, then git add and git commit to finish the merge. Nothing is lost.

Command cheatsheet

The twelve commands that cover almost everything you'll do in your first year.

CommandWhat it does
git init -b mainStart tracking the current folder
git clone URLDownload an existing repository
git statusShow what has changed since the last commit
git add .Stage every change for the next commit
git commit -m "…"Save the staged changes into history
git pushSend your commits up to GitHub
git pullBring everyone else's commits down
git log --onelineList the history, one line per commit
git diffShow the exact lines you've changed
git checkout -b NAMECreate a branch and switch to it
git switch mainGo back to the main branch
git remote -vShow which GitHub URL this folder points at
